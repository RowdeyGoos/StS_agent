## Shared API and lineage

Namespace Sts2AgentBridge.Successors.EventOrchestratorV1. A draft core API file
is independently reviewed and hash-frozen before dependent implementation. Its
ledger pin and this contract jointly define the interface; no unreviewed semantic
change may be silently accepted after consumers begin.

Child kind is the closed enum Item or CardSelection. Correlation binds the exact
accepted RoomFlowDispatchReceipt object, kind and strictly increasing child
ordinal1..4. One active child only. Native capture binds run/player/event-room/map,
exact option/controller references, foreground screen and immutable child policy
or factory. Policy/factory identity is part of publication and immediate stale
revalidation BEFORE dispatch. Cheese operation/cardinality/domain/commit mode
must already be known at that point; a later selector cannot retrofit a policy.
The generic ordinary path retains only the prior item-child eligibility.

After exactly one accepted option receipt, the first eligible foreground child
may be admitted only with the matching retained policy/factory and context.
Cheese/GORGE permits only CardSelection with its exact add2 descriptor; generic
ordinary choices permit only Item under the existing rule. No cross-kind fallback.
Each factory is claimed once. Claimed factory and foreground-screen identities
become lifetime tombstones after claim, resolution or failure and cannot seed a
later ordinal. The descriptor/factory is reserved with the exact parent action.
No startup selector, preselection, completed task, foreign screen, substituted
policy or later matching state can be adopted.

The accepted option's child window closes permanently when a changed parent
structural projection, final Proceed, foreign/unsupported overlay or another
terminal transition is observed before a supported child. Only transient absence
with the exact bound parent context may keep it open. A later matching child
cannot reopen that receipt; another child needs a new accepted parent action.
Child kind/ordinal/parent-decision/parent-action are public correlation values;
opaque references never leave the bridge. Typed child broker interfaces expose
actual item or card Read/Apply values and active/resolved/failed status.

Preserve lifetime stable-option reservations and A-B-A denial for this increment.
Repeated choices requiring reuse of a stable key remain a documented coverage
gap until a separate exact loop policy is accepted. A text-only change or child
completion alone cannot create a fresh ordinary option decision. Parent recapture
must satisfy the unchanged structural transition rules and exact context.

On child resolution, latch its correlated result and dispose it before resuming
the parent. Retain failed cleanup ownership and terminalize; never drop or replace
an unsuccessfully disposed child. Repeated old child screens cannot become new
episodes. A later child needs another accepted unreserved parent option and a
new ordinal. Ordinary transition observations are not independently reconciled
HP/gold effects. Final completion requires explicit singleton Proceed, its exact
accepted receipt and the same bound map open/travel-enabled/nontraveling witness.

## Wire and host

Use exactly one new decision/action pair:
`/probe/event-orchestrator-v1/public/decision` and
`/probe/event-orchestrator-v1/public/action`. No independent old item/card route
is exposed. The current response envelope identifies the active parent or typed
child with kind, ordinal and accepted parent receipt IDs. A child action carries
that exact envelope correlation in addition to its decision/action IDs. Parent
actions use the empty child correlation. Requests cannot select or construct a
child. Wrong kind, ordinal, receipt, stage, nonce, action or missing publication
fails before native dispatch. One active publication only; no dynamic routes.

Serialize bounded public scalar data only. Child payloads preserve the frozen
item/card formats and validators; the outer envelope provides episode lineage.
Strict keys, duplicate rejection, UTF-8, canonical IDs, depth/body bounds,
monotonic histories and immutable candidate domains remain enforced. Request
and response buffers have explicit owners and are cleared after consumption;
provider text and card values remain transient. Summary persists only fixed
status/reason codes and attempted/accepted/reconciled or transition/child counts.

The Python host takes a REQUIRED decision-provider argument. It receives an
deeply immutable copy of the currently published bounded public decision and returns
one action ID from the advertised legal list. An explicitly selected FirstLegal
provider supplies deterministic fixtures; no hidden controller choice or LLM
strategy is introduced. Invoke at most once per decision. Validate type, legal
membership, unchanged context and deadline before dispatch. Exceptions, invalid
output, reentry into this controller or an expired deadline stop with no retry.
The host does not claim to police arbitrary external work captured by a callback. Synchronous provider
work is cooperative; check the same overall deadline before and after it rather
than claiming Python can preempt arbitrary callback code. No game action occurs
after a late return. Native recapture remains the final stale-action guard.

One overall30-second monotonic host budget, at most2048 reads,12 parent actions,
4 child episodes and52 total actions. Frozen per-child limits remain: item one
accepted action, card at most10. Native per-pending read bound256 remains.
No budget reset between children; malformed/unsupported/uncertain work stops the
whole event. No fallback route, retry, replay or background provider action.
