## HTTP boundary

Production exposes only the frozen GET item-decision and POST item-action routes. Application bodies remain byte-exact item_probe_v1; no new envelope/status/schema is introduced. Each TCP connection carries exactly one bodyless request and one response followed by close. After sendall the client must call shutdown(SHUT_WR); the server requires EOF after the exact request head within its header/connection deadline before parsing, authenticating or queueing. Any bytes after the head terminator reject the entire request, including fragmented/delayed trailing bytes. Missing half-close times out without core access. The only accepted request bytes have this exact case, order and spacing (placeholders stand for validated bytes):

```text
GET /probe/item-v1/public/item-decision HTTP/1.1\r\n
Host: 127.0.0.1:43117\r\n
Authorization: Bearer <64 lowercase hex bytes>\r\n
Accept: application/json\r\n
Connection: close\r\n
\r\n
```

POST replaces the first line with `/probe/item-v1/public/item-action`, retains Host/Authorization/Accept, inserts `X-Sts2-Decision-Id: <64 lowercase hex>` then `X-Sts2-Action-Id: collect:<canonical 0..255>` immediately before Connection. No other method/route/header/order/casing/framing is accepted. In particular Origin, duplicate/unknown headers, URL/query/encoded paths, Content-Length including zero, Transfer-Encoding, Expect, bodies, pipelining, bare LF and extra bytes are rejected. Reject before native access. Do not decode authorization into a managed string. Authentication is constant-time over the bounded candidate bytes after syntactic checks. After exact parse and authentication, reserve a POST atomically BEFORE authenticated rate limiting and queue/admission checks. A post-reservation rate failure makes the runtime terminal, exactly like a queue failure. Pre-authentication/handler rejection can remain unreserved because no valid authenticated POST has been classified.

Use the existing conservative caps: backlog 8, at most 4 concurrent handlers, pre-authentication bucket 32/sec burst16, authenticated bucket20/sec burst10, request line128 bytes, head4096 (4097-byte detection buffer), target64, at most8 headers, name32 and value512. Buckets live for the runtime activation; requests cannot reset them. Header read is at most1 second, write at most1 second, total connection lifetime at most2 seconds. Admission never spawns an unbounded worker queue. A rejected/unauthorized/rate-limited/malformed/unavailable request closes silently; there is no retry hint, mutation-state claim or reflection of actor input.

For successful application-service dispatch, return exactly this ordered header plus its unchanged body:

```text
HTTP/1.1 200 OK\r\n
Content-Type: application/json; charset=utf-8\r\n
Content-Length: <canonical positive decimal 1..4096>\r\n
Cache-Control: no-store\r\n
X-Content-Type-Options: nosniff\r\n
Connection: close\r\n
\r\n
```

All service statuses, including accepted/rejected/uncertain/error, use that wrapper; the host owns their meaning. No service result after a connection deadline is sent. Queue/service/serialization/infrastructure failures close silently; no old v0 transport envelope is reused. Server request, response-body and assembled-response arrays are zeroed on every owned exit, including partial write, cancellation and shutdown. The fixed-time credential copy is zeroed at teardown. No request/response/credential/exception logging.

## Frame ownership, uncertainty and shutdown

One queue per runtime, capacity2 including claimed work, at most2 work items per DrainFrame; at most250ms slot admission plus500ms result wait. Only the owned frame thread invokes the frozen service, so no native observation or dispatch occurs on network workers. The processor reserves the runtime's sole authenticated, syntactically valid POST attempt before authenticated rate limiting and queue admission; any later POST closes without another submit, even if the first was rejected, timed out, lost or could not enter the queue. The frozen service's own one-attempt reservation remains in place.

Waiting work cancelled/timed out before claim never executes. Claimed work can finish after timeout or Stop; never claim that a timeout proves no mutation. If ownership of a result did not transfer to the requester, the queue must zero the late byte array exactly once on completion and release its slot exactly once. A live requester receiving a result becomes its sole owner. Resolve timeout/completion races under one explicit synchronization rule; no dropped unowned arrays. A failure after POST submission makes transport processing terminal for that runtime (further requests close); already claimed work may settle and clean up but cannot be retried or adopted. A failed/lost response after a completed socket send may be unknowable to the server; the reserved attempt and strict host correlation still prevent retry/adoption.

Stop first rejects admission, stops accepting sockets, cancels queued-unclaimed work and wakes its waiters. Close/cancel active sockets and wait at most the fixed join budget for network workers and claimed work; false means incomplete teardown. Do not dispose synchronization primitives still used by claimed work or active workers. Cleanup is idempotent. No new session/listener can be started from the same runtime after Stop/Dispose.

## Python connector

Public API: `run_authenticated_collection(credential: bytearray, *, clock=time.monotonic, sleep=time.sleep) -> dict`. It invokes the unchanged item_wire_v1 host and returns only that frozen fixed result. There is no public raw exchange, endpoint parameter, default connector discovery, config reader, CLI, logging or ML import. Exact mutable credential ownership transfers for the whole invocation and it is zeroed on all exits; invalid exact buffers are also zeroed and yield the fixed internal_failure. Immutable/subclass/null credentials do not transfer and produce that same fixed failure. Cancellation exceptions propagate after cleanup.

Import only `from item_wire_v1.host import TransportFailure, run_collection` from the verified sibling source image; the checker explicitly installs that source parent on the isolated Python path and rejects ambient-package fallback. Each injected host exchange validates its method/route/metadata, creates one `socket.socket(AF_INET, SOCK_STREAM)`, connects directly to `("127.0.0.1",43117)`, sends the canonical request once with sendall, calls shutdown(SHUT_WR), receives its one bounded response and closes. Half-close failure has the same cleanup/TransportFailure rule as every other socket failure. No getaddrinfo, create_connection, redirect/proxy, TLS, fallback or retry. Build the request in a bytearray without decoding/copying the credential into immutable storage. Zero every owned request buffer. One 3-second exchange deadline is bounded by the host's existing absolute15-second deadline, with each socket operation capped at1 second and before/after I/O checks. Any socket/framing/deadline/close failure becomes bare frozen TransportFailure without exception text/chaining; the host stops. A body that returns after the host deadline can never pass its existing post-exchange check.

Receive into a bounded mutable accumulator with chunks at most1024 bytes; header terminator must end within1024 bytes, body1..4096, combined at most5120 bytes. Validate the exact HTTP header above and canonical Content-Length; require EOF with exactly the declared bytes, no truncation/trailer/extra response. Never follow an error or redirect. HTTP/framing faults are transport_failure; a canonical HTTP response containing malformed item JSON remains invalid_response in the frozen host. Only after framing/EOF/socket close succeeds, delete the header in place and transfer the same bytearray to the host, which zeroes it. On every earlier error/late/cancellation exit the connector zeroes the response itself. Preserve fixed failure reports and cancellation semantics of the frozen host.

A private `_run_with_socket_factory(credential, socket_factory, *, clock, sleep)` may support tests. Production hardwires the fixed socket creation. A redirecting wrapper lives only in tests/cross gate; it asserts the requested production endpoint and substitutes an ephemeral synthetic loopback endpoint. No production configurable port.
